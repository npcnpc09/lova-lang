# LOVA

[English](README.md) · **中文**

**一门为 AI 而生的编程语言：让 AI 写得顺、跑得稳、修得快。**

**主页：** [npcnpc09.github.io/lova-lang](https://npcnpc09.github.io/lova-lang/) —— 一页看完，背景是二十五万颗粒子（源码在 `docs/`）。

*现状：**1.0，语言已经完整，可以上手用了。**
十条设计公理都已经在语言里落地，每一条都有实验数据撑着。64 个操作符的表已经用满（63 个操作符加一个 `END`），有整数、列表、字符串、闭包、`letrec`、循环、能抛能接的错误处理、带血统记录的"程序即值"、会自己演化的函数种群、按声明的权限访问文件 / 时钟 / 网络，还有一个持久化的 map。配套有五趟静态检查的编译器、按类型约束生成代码的生成器、用 LOVA 自己写的标准库、模块、命令行、给 AI 智能体用的 MCP 服务器，以及 1 116 个测试。参考实现是一个只用 Python 标准库的解释器；日常跑程序用的是 Rust 写的原生运行时 —— 字节码虚拟机，每秒一千多万步，跟解释器在 1 023 条黄金记录上逐步比对过，一步不差。同一个运行时还能作为扩展装进 Godot 4，让游戏规则用 LOVA 写、画面交给引擎。它没有浮点数、没有命名空间、没有并发；文末"LOVA 还做不到什么"一节，如实列了出来。*

## 一句话介绍

在 LOVA 之前，所有编程语言都是为人造的 —— 让人学得会、读得懂、审得动。**LOVA 是第一门为 AI 造的语言。**

LOVA 只有一个目标：**让 AI 用起来比用任何别的语言都省事。** 不是追求更紧凑、更新奇，而是四件实在的事：从写出来到跑对，尝试次数更少；每次出错，理解它花的上下文更少；安全地运行代码，不需要额外搭沙箱；写过的代码，后面的程序能复用、能修、能追溯。错误模型、契约、权限声明、血统记录、演化机制，都是为这四件事服务的；底层的整数编码只是程序的存储格式和身份证，不是卖点。**这门语言的第一读者、第一作者、第一执行者，都是 AI**；人排在第二位。

### 离这个目标还有多远

目标用四个数来量：同样的题，LOVA 和 Python 各做一遍，每次都用全新的模型会话。现在各自的位置：

| 指标 | 现状 | 依据 |
|---|---|---|
| 1. 从写出来到跑对的尝试次数 | 多数题持平；搜索类的重题落后，差距在缩小 | 实验 17-20；实验 31：步数超限时会说明程序实际需要多少步，搜索类故障修好 17/18，不给这个信息是 14/18（试点） |
| 2. 每次出错花的上下文 | **同类错误持平** | 实验 30：出错只回一行——在哪、要 patch 的范围、错在哪——193 个字符，原来的结构化异常是 877；结果错了这一类，LOVA 75、Python 71 |
| 3. 安全运行要搭的脚手架 | **领先** | 在步数预算和权限边界下调一个函数，对比开子进程加超时 |
| 4. 复用、修复、追溯 | 110-160 行的程序上修复**领先**；复用和追溯还没证明 | 实验 29 |

还有一件事也被数据定了下来：现在的模型是先想好树、再转写成整数，所以整数底层是程序的存储、传输和身份，不是模型思考的方式（实验 24）。数据支持的留下，不支持的就改。

而且它是开源的，不属于任何人。谁都可以扩展它、改写它，乃至推倒重来 —— 判断标准只有一条：AI 用它，是不是干得更多、更省事。

```lova
(defn square [n] (⊗ n n))
(square 7)
```

上面这段只是给人看的"投影"。程序本身是一串整数，文本只是把它打印得好看一点。`⊗` 就是 `mul`，`defn` 会展开成 `let` + `lambda`，函数调用展开成 `apply`，所以底层真正存的是：

```lova
(let 0 (lambda 1 (mul (ref 1) (ref 1))) (apply (ref 0) 7))
```

变量名在解析时就换成了整数编号，打印回来也是编号 —— 因为整数才是程序本体（公理 1）。所有语法糖都展开到那 64 个操作符，不引入任何新语义。

## 三个阶段

| 阶段 | 长什么样 | 进度 |
|---|---|---|
| **一、有文本的 LOVA** | 类 Lisp 的 s 表达式，和 token 一一对应 | **现在在这里**，主要用来审计 |
| **二、AI 为主的 LOVA** | 一个字符对应一个字节，没有括号（`core/surface2.py`） | **已实现并测过**（实验 14）；微调模型还没做 |
| **三、纯 AI 的 LOVA** | 没有文本，程序就是整数；人想看就调 `(explain program)` | 终极目标 |

## 已经有什么

- **64 个核心操作符**（8 族 × 8 个），每个一字节 —— 52 个有运行时语义，12 个保留（`spec/tokens.md`，由 `spec/generate_tokens_md.py` 自动生成）
- **数据结构** —— 一个 cons 单元（`nil` / `cons` / `head` / `tail` / `nil?`）就撑起了序对、列表和字符串（字符串就是码点列表），所以 `"abc"` 只是语法糖，不占操作符表的格子（`spec/token-budget.md`）
- **两种书写形式** —— 第一阶段的 s 表达式，给人写、给人审；第二阶段是字节编码的直接投影，一个字符一个字节，没有括号，两个方向互转无损（`core/surface2.py`）
- **IO** —— `stdout` / `stdin`，语言里仅有的不确定因素，`static_analyze` 会标出来
- **用 LOVA 写的标准库** —— `lib/prelude.lova`，`map`、`filter`、`fold`、`range`、`append`、`reverse`、`digits`、`println` 全在里面，没有一个是内建。引入它不花钱：编译器的 `drop-unused` 会把没用到的定义全部剪掉，一个不用标准库的程序从 474 个节点缩回 1 个
- **命令行** —— `lova run | repl | emit | analyze | mcp`（`core/cli.py`）
- **MCP 服务器** —— `lova mcp` 通过 stdio 对外提供 `lova_execute`、`lova_static_analyze`、`lova_valid_next`、`lova_emit` 四个工具，任何支持 MCP 的宿主都能接，除标准库外零依赖。`lova_valid_next` 就是把公理 3 做成了服务（`core/mcp_server.py`）
- **统一的错误模型，程序内部也能用** —— 所有故障都是同一种结构化异常；`(when-anomaly body handler)` 把异常码交给程序自己处理。唯一拦不住的是运行时的终止上限 —— 这是故意的
- **函数种群** —— 公理 6 在语言里的样子：`(defpop scorer p1 p2 …)` 建一个池子，`(evolve pop)` 跑一代，`(select pop 0)` 取最优，赢家能说出自己是怎么来的。实验 15 把整个自愈实验写成了一个 LOVA 程序
- **程序即值** —— `quote` / `eval`，加上整个 Meta 族：`(explain p)` 把程序变成文本，`(hash p)` 给出它的整数，`(why p)` / `(lineage-query p)` / `(ancestor-of a b)` 查它的来历，`(clone p)` / `(mutate p 30)` 派生新程序并记下过程，`(read text)` 是 `explain` 的反向 —— 程序可以拼一段文本，读成程序，再 `eval`。公理 5 在语言内成立了，第三阶段要用的 `explain` 也已经有了
- **访问外界要先声明** —— `(boundary "fs-read clock" body)` 声明 `body` 里允许哪些副作用；`fs-read` / `fs-write` / `clock` 就是副作用。没声明就用，编译器拒绝；声明了但宿主没授权（`lova run --allow fs-read,clock`），运行时拒绝；默认什么都不给。网络用 UDP 的 `net-send` / `net-recv`：程序只说"我要用网络"，地址由宿主给（`--allow net=host:port`、`net=:port`）。这就是公理 4 在副作用上的体现
- **够写真程序的标准库** —— 列表函数用迭代不用递归（`len` / `map` / `filter` / `fold` / `sort` / `take` / `zip` ……），文本函数（`words` / `lines` / `split` / `join` / `parse-int` / `text-of`），持久化 **map**（`map-put` / `map-get` / `map-pairs`，键可以是整数或文本），还有 `signal`，让库代码也能抛出调用方可以接住的结构化异常。验收程序是 `apps/wordfreq.lova`（M22）
- **库** —— `(use "evolution")` 引入 `lib/evolution.lova`，里面用六个演化操作符九行写出了一条自定义演化规则；`(use "prelude")` 就是标准库，命令行默认加载。引入是文本级的，只引一次，经 `drop-unused` 之后不花任何代价
- **抽象能力** —— 支持柯里化的一元闭包、`letrec`、循环组合子，递归和无限迭代都写得出来。两道常开的上限（`MAX_CALL_DEPTH`、`MAX_STEPS`）保证程序不会挂死，只会抛一个结构化异常（`core/runtime.py`）
- **按类型生成代码** —— 程序写到一半，下一个合法 token 的集合总是可以算出来的，所以类型不对的程序根本生成不出来（`core/types.py`、`core/generator.py`）
- **资源约束是类型的一部分** —— 预算和副作用写在函数签名里，违反了要么编译不过，要么运行时触发 Δ 陷阱（`core/conservation.py`）
- **用"惊异"代替栈回溯** —— 程序偏离预期时抛结构化异常；Δ 陷阱扫描器能定位到出错的最深一层子表达式，*连修正值一起给出*（`core/runtime.py`）
- **血统** —— 每个程序都带着来源信息，在语言里就能查（`core/lineage.py`）
- **种群** —— 一个函数是一群互相竞争的变体，不是一份固定的定义（`core/populations.py`）
- **编译器** —— 作用域检查、类型检查、常量折叠；编译错误和运行时异常是同一种格式，AI 只需要写一个错误处理器（`core/compiler.py`）
- **LOVABench** —— 5 类 60 题 / 180 个用例，带参考评测器（`corpus/`）。注意这些题都是 M9 之前出的，没有一道涉及递归或循环（Q33）

## 快速开始

需要 Python 3.10 以上。核心**零依赖**，PyPy 也能直接跑。如果装了 Rust，进 `native/lova-rt` 执行 `cargo build --release` 就能编出原生运行时 —— 每秒一千到一千二百万步，是 CPython 的二十倍 —— 之后 `lova run` 会自动用它（`--native off` 强制用 Python 解释器，`--native on` 会在用不上时告诉你原因）。两个运行时给出同样的值、同样的异常、同样的步数，`corpus/golden/` 里逐条核对过。编译结果缓存在 `$LOVA_CACHE`（Windows 默认 `%LOCALAPPDATA%\lova\cache`，其他系统 `~/.cache/lova`），键由源码、用到的库和实现的哈希组成，所以引入 3D 库的程序第二次运行能省掉一两秒的解析；`LOVA_CACHE=off` 可以关掉。

```bash
git clone <this-repo> lova && cd lova
export PYTHONPATH="$PWD"

# 跑一个程序
python -m core.cli run apps/is_prime.lova 1999      # => 1
python -m core.cli run apps/palindrome.lova racecar # => 1
python -m core.cli run apps/palindrome.lova 's="7"'  # 加引号就是文本，哪怕是 "7"

# 和一个不会输的井字棋 AI 对弈
python -m core.cli run apps/tictactoe.lova 0

# 在预算限制下批量跑不可信程序，一行一个，逐个报告结果
python -m core.cli run apps/sandbox.lova 5000 < programs.txt

# 让一池程序朝目标演化，然后问赢家它是怎么来的
python -m core.cli run apps/evolve.lova 42 60

# 修复一个违反契约的程序，靠"惊异"引导
python -m core.cli run apps/repair.lova 42 30 200

# 一个 Python 写的网页壳，唯一的业务规则是一段 LOVA，可以在页面上改、改坏也没事
python apps/shell/policy_app.py       # http://127.0.0.1:8765

# 坦克大战：窗口是 Python 画的，游戏规则全是 LOVA
python apps/tanks/tank_game.py        # 方向键移动，空格开火
python -m core.cli run apps/tanks.lova 7   # 同一个游戏的终端版，一回合一回合来
python apps/g2048/game2048.py 7       # 2048，从 gabrielecirulli/2048 移植
python apps/platformer/platformer.py  # Kenney 的 3D 平台跳跃，从 GDScript 移植
python apps/fps/fps.py                # Kenney 的 FPS 套件：两把枪，四个会飞的敌人
#   上面两个装了 pygame 就走 SDL 窗口
#   （`pip install pygame` 之后画面更流畅；没装就退回 Tk，
#   `--host tk` / `--host sdl` 可以手动选。`--bench N` 打印帧耗时）
python apps/godot/fps/build.py path/to/Starter-Kit-FPS --run   # 把 FPS 规则跑进 Godot

# 交互式会话，标准库已加载
python -m core.cli repl

# 把程序输出成第二阶段形式、字节，或者一个整数
python -m core.cli emit apps/coprime.lova 14 15 --form stage2
python -m core.cli emit apps/coprime.lova 14 15 --form int

# 不运行，先看看这个程序会做什么
python -m core.cli analyze apps/collatz.lova 27

# 跑程序自带的示例
python -m core.cli check apps/tictactoe.lova 0

# 跑测试（1 116 个，只用标准库的 unittest）
python -m unittest discover -s tests

# PyPy 下同样全部通过
pypy -m unittest discover -s tests -t .

# 跑一个实验
python experiments/experiment_01_hello_lova.py

# 每个 app 也有自己的 Python 驱动，会把整条流水线打印出来
#   （解析 → 分析 → 编译 → 编码 → 求值）
python apps/is_perfect.py 28
```

也可以直接安装 —— wheel 里包含核心、LOVA 库和语料，并提供 `lova` 命令：


### 接给 AI 用

`lova mcp` 在 stdin/stdout 上说 MCP 协议。Claude Code、Claude Desktop、Cursor 等任何 MCP 宿主接上之后能拿到四个工具：运行程序（权限要显式给）、不运行只分析、问"写到这里下一个 token 能是什么"、把程序转成第二阶段 / 字节 / 整数。出错时只回一行：阶段、类型、`行:列`、`lova_patch` 要用的 `[start,end)` 范围、那一处的原文、错在哪；步数超限时还会说明程序实际需要多少步。要完整的结构化异常，传 `report: "full"`。

```json
{"mcpServers": {"lova": {"command": "lova", "args": ["mcp"]}}}
```

不想安装的话，直接从仓库目录启动：`"command": "python", "args": ["-m", "core.cli", "mcp"], "cwd": "/path/to/lova-lang"`。`apps/mcp_demo.py` 会通过管道把四个工具各调一遍。

14 个实验全部能跑。实验 03 和 07 在题库从 20 题扩到 60 题之后曾经失效，M13 修好了，下面引用的都是 60 题的数字。

实验 11 额外需要 `tiktoken`：

```bash
pip install -e ".[experiments]"
```

## 这些程序证明了什么

`apps/` 里有二十三个程序，每一个都是为了用这门语言做点真事而写的，写完就留作测试。它们说明：

- **能跑游戏。** 坦克大战，实时的：八个敌人从网格顶部进场，随机游荡，直到能直线看见你或你的基地，然后开火。移动、子弹能打穿的墙、敌人的瞄准、刷新、胜负判定 —— 所有规则都在 `lib/tanks.lova`，大约 250 行纯函数，作用在一个"世界"记录上，自带十八个示例，`lova check` 会跑。窗口是 tkinter，只负责画像素和读按键：每秒十次，把当前世界和你按的键交给 LOVA，拿回下一个世界，画出来。一回合大约 10 000 步，预算 200 000，角落里实时显示；如果哪条规则失控，屏幕上会出现一个结构化异常，而不是窗口卡死。同一套规则在终端里也能一回合一回合地玩。

  ![坦克大战：窗口是 Python，规则全是 LOVA](apps/tanks/screenshot.png)

  ```bash
  python apps/tanks/tank_game.py             # 方向键移动，空格开火，R 重开
  python -m core.cli run apps/tanks.lova 7   # 终端版
  ```

- **能把别人的游戏移植过来，还能证明移植没走样。** 2048，原版是 [gabrielecirulli/2048](https://github.com/gabrielecirulli/2048)（MIT）。`lib/g2048.lova` 是对着原版的 `js/game_manager.js` 写的：同样的遍历顺序、同样的"滑到最远"算法、同样的"这一步合成过的块不能再合"、同样的计分、同样的九成概率出 2。"移植和原版行为一致"这件事不是嘴上说的：`tests/test_2048.py` 里放了一份原版逻辑的 Python 转写，两边在随机局面上一起跑，逐格比对。**10 000 个局面，零分歧。** 唯一的故意差异是随机数 —— 原版用 `Math.random`，没法重放；这里把随机数生成器串进了世界状态，一个种子对应一整局。顺带一提，这次移植还揪出了我们编译器里的一个真 bug：`drop-unused` 对"因副作用而保留的绑定"处理有误。

  ![2048：窗口是 Python，规则是 LOVA](apps/g2048/screenshot.png)

  ```bash
  python apps/g2048/game2048.py 7            # 窗口版，用原版配色
  python -m core.cli run apps/g2048.lova 7   # 终端版
  ```

- **还有一个 3D 平台跳跃，从 Kenney 的入门套件移植。** `lib/platformer.lova` 装的是 [KenneyNL/Starter-Kit-3D-Platformer](https://github.com/KenneyNL/Starter-Kit-3D-Platformer)（MIT，约 1 200 星）的全部规则，对着它的 GDScript 写：角色能走、二段跳、落地时压扁一下；金币上下浮动并旋转；有会塌的平台、从下面顶碎的砖；相机跟随、转向、缩放；掉出地图就重来 —— 每个常量都和套件一模一样。`lib/scene3d.lova` 负责把套件的模型画进一个可以移动的相机视角：四十六个物体的摆放、旋转、倾斜、剔除、打光，**每 tick 约 4 000 步，每帧约 150 000 步**。模型和关卡都是套件原装的，由 `apps/platformer/import_kit.py` 从 `.glb` 和场景文件里读出来，各自减面到预算内，颜色保留。`tests/test_platformer.py` 把套件的五个脚本转写成 Python，和移植版在同一段脚本化操作下逐 tick 对比：**每个位置的误差在四毫米以内**，捡到同样的金币，在同一 tick 掉出地图。

  ![Kenney 的平台跳跃关卡：窗口是 Python，游戏是 LOVA](apps/platformer/screenshot.png)


- **逻辑第一次就跑对。** 词频统计、几个游戏、日志汇总、批处理、沙箱 —— 每个程序的逻辑第一次执行就给出了正确结果。出错的时候，要么编译期就抓住并给出修复提示，要么运行时抛一个结构化异常，从来没有崩溃、没有栈回溯。
- **失败也是数据。** 沙箱一行一个地跑不可信程序，每个程序要么报哈希和结果，要么报故障的*名字*：死循环撞上 `budget`，读文件撞上没声明的边界，不是程序的文本会被明确说成"不是程序"。沙箱本身什么权限都不需要，也不可能被程序碰到。
- **契约是程序自己定的。** 批处理给每个任务单独设预算，统计超支的有几个；修复器声明一条 `conserve` 契约，对目标程序反复变异直到满足，只保留让"惊异"变小的变异。300 个任务里 219 个在预算内完成，和外部推算的数字完全吻合；三个修复目标分别在 39、37、20 次内收敛，可复现。
- **来历在程序内部就能查。** 演化出的赢家和修好的程序，各自能打印出自己的代码、代数、存在的理由和血统长度，全程不借 Python 的手。
- **访问外界要先声明。** 两个进程互发数据报、读一个文件、查一次时钟，每一样都在一个边界之内：程序声明种类，宿主指定地址。没声明的副作用碰不到，编译器在运行前就会拦下。
- **程序就是整数。** 所有程序从第二阶段形式重新读回来再跑，输出和结果完全相同，包括那个 3 000 字符的游戏。
- **模型看一页就会写。** 一个新开的 Claude 会话，只给 `corpus/language_card.md` 这一页说明，做 LOVABench v3 的 80 道题，每题只答一次、不许运行，**答对 79 道** —— 和它用 Python 做同样的题得分一样；算法类两边都是 20 道全对。也就是说，学这门语言对模型来说没有额外成本，但换来了 Python 没有的契约、预算和结构化错误（`journal/experiment_17.md`）。
- **模型能照着错误信息修好。** 让一个新会话自己跑代码、自己看结果，十道涉及循环、列表、文本的题：两种语言都全对，LOVA 提交了十一次，Python 十次。LOVA 多出的那一次是一个编译错误，报错里带了出错的片段、行号和应该改成什么，下一次提交就过了。LOVA 的答案是在预算内、不给任何权限地当函数调用跑的；Python 的答案得起子进程加超时（`journal/experiment_18.md`）。再往上，八道更大的题、每种语言三个会话，遇到的每一个编译错误都在下一次提交修好，会话自己评价诊断信息"极好"；现在超预算时还会报告步数花在了哪些函数上（`journal/experiment_19.md`）。
- **有 Python 的地方就能跑，有 Rust 的地方跑得快。** 核心零依赖，CPython 和 PyPy 都能跑，测试套件两边都能跑；原生运行时跑的是同一串字节，每秒一千多万步，还能装进 Godot。
- **文本是一等值。** 字符串字面量就是一个节点；`words`、`split`、`join`、`parse-int` 这些各是一个操作符；一万行文本的词频统计，CPython 上从 28 秒降到 5.5 秒（M25）。
- **报错指到位置，修复就是打补丁。** 每个异常都带着出错表达式的源码范围和原文；MCP 服务器的 `lova_patch` 直接替换那个范围 —— 或者替换某个 def 里的一段文本 —— 然后检查结果。一个跑挂的 `example` 会说出改哪一处就能通过，连替换文本都给好。AI 的工作流就是"运行、打补丁、再运行"，一次修复的代价就是补丁本身的大小。
- **程序回答问题，不用通读。** `lova_show` 按名字取一个 def，带范围和参数；`lova_scope` 告诉你某个位置有哪些变量；`lova_callers` 告诉你谁调用谁 —— AI 读的是它问到的那一个定义，不是整个文件。
- **写程序时发现的问题，当天就修。** 写这批程序暴露了四个边角问题 —— 输入、自引用、程序 id、参数 —— 每一个当天就变成了一项编译检查、一个标准库函数或一种命令行用法，每种情况都有测试。过程都记在日志里。

## LOVA 适合放在哪

每门语言都有自己的位置：Python 是胶水和笔记本，Rust 管系统层，JavaScript 管浏览器，Erlang 是永不宕机的交换机。LOVA 的位置是 **AI 写、机器跑、人不需要读的代码**：智能体整天生成的小程序，系统开放给用户或模型改的规则和策略，长期运行的服务自己调整的参数逻辑。它给这个位置带来的，是一组通用语言都没有的保证。

### 和其他语言比

| 程序能得到什么 | Python | Rust | Haskell | Clojure | Unison | **LOVA** |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| 错误是结构化数据，不是文本 | – | 部分 | 部分 | – | – | **有** |
| 生成器根本写不出畸形程序 | – | – | – | – | – | **有** |
| 副作用由程序声明、宿主授权 | – | – | 类型化 | – | 部分 | **有** |
| 每次运行都有上限（步数和深度） | – | – | – | – | – | **有** |
| 资源契约写在程序里 | – | – | – | – | – | **有** |
| 程序是一等数据 | – | – | – | 有 | 有 | **有** |
| 来历在程序内可查 | – | – | – | – | 部分 | **有** |
| 函数是一个会演化的种群 | – | – | – | – | – | **有** |
| 靠程序自身的偏差引导修复 | – | – | – | – | – | **有** |
| 零依赖，同一份核心跑在 CPython 和 PyPy 上 | 核心 | – | – | JVM | 运行时 | **有** |

按表里的顺序，LOVA 分别是怎么做到的：

1. 每个错误都带种类、位置路径和修复提示，编译期和运行期一个格式；`when-anomaly` 让程序接住自己的错误，按错误码分支。
2. `valid_next` 在每一步给出合法的下一个 token，所以生成出来的程序不可能有语法错误或作用域错误。
3. `(boundary "fs-read" ...)` 声明副作用的种类，`--allow` 指定具体地址；没声明就用，编译不过。
4. 步数上限和深度上限是内建的：死循环变成一个结构化异常，不会挂死，超预算时还会告诉你步数去了哪些函数。
5. `(budget n ...)` 可以按调用、按任务、按每一行不可信代码设；超支了程序自己能接住。
6. `quote`、`eval`、`read`、`explain`、`hash`：程序是一个整数，也是语言里可以操作的值。
7. `why`、`generation`、`lineage-query` 都是操作符；记录在值里，不在旁边的什么日志里。
8. `defpop`、`evolve`、`select`：赢家能说出自己的血统。
9. `conserve` 定契约，`surprise` 量偏差，`mutate` 提方案；三个目标分别 39、37、20 次修好，可复现。
10. 核心只用标准库；1 116 个测试的套件在两个解释器上都能跑。

支撑"模型学它零成本"这句话的数据：一个新开的 Claude 会话看一页 LOVA 说明，80 道基准题一次作答对 79 道，和它的 Python 成绩一模一样。

离 LOVA 更近的，其实是那些可嵌入、带沙箱的规则语言——Starlark、CEL、挂了指令钩子的 Lua、带 fuel 的 WebAssembly。运行有上限、访问外界要宿主授权，这两点它们也有。LOVA 多出来的，是表里其余几项，以及一种写给模型看的错误：一行字，说清在哪、错在哪、超了多少预算。

上面十项里有三项在别处零散地存在过：类型里带副作用（Haskell、Koka）、代码即数据（Lisp、Unison）、自愈系统（Erlang）。没有哪门语言同时有这三项，更没有哪门有另外七项。LOVA 是把它们放到一起的那门语言，只用了 64 个操作符。

### 用在哪里

**AI 智能体的沙箱。** 干活的智能体随时要算点东西 —— 求个和、转个格式、验个条件 —— 现在的做法是写段 Python 扔进容器。换成 LOVA，程序不会挂死，碰不到没声明的文件和网络，每次失败都是结构化数据。`apps/sandbox.lova` 一行一个地跑不可信程序，在预算内，逐个报告摘要和结果或者故障名，它自己只有十二行、不需要任何权限。`lova mcp` 把这套能力开放给任何宿主。

**应用里的规则层。** 界面、存储、网络用你现在的语言写；真正*做决定*的那一小块 —— 定价规则、策略、用户或模型提交的脚本 —— 用 LOVA 写，可以在线改，在预算内、无权限地运行，怎么改也伤不到宿主应用。`apps/shell/policy_app.py` 是个 Python 网页壳，唯一的业务逻辑是一段可以在浏览器里改坏的 LOVA；`apps/tanks/tank_game.py` 是个坦克游戏，移动、子弹、敌人瞄准、胜负全在 `lib/tanks.lova` 里，Python 窗口每秒调用十次，自己只管画和读键盘。

**需要审计的 AI 生成代码。** 程序是一个带血统的整数：哪个模型、什么时候、从哪个父版本、为什么。`apps/repair.lova` 和 `apps/evolve.lova` 会打印出它们产出程序的完整血统。AI 写的代码上线前要追溯的场合，记录就在值里，不用另找。

**自己调参的服务。** 把服务的启发式逻辑 —— 重试策略、排序权重、阈值 —— 做成一个 `defpop` 种群：变体竞争，差的淘汰，好的克隆变异，每个版本都能说出自己为什么存在。`conserve` 和 `budget` 契约限定演化的边界。

**受约束解码的目标语言。** 小模型或端侧模型必须产出能编译的代码时，`valid_next` 就是语法约束：每一步只给合法的 token。微调语料（`corpus/finetune.py`，3 000 对验证过的样本）和一页语言卡都准备好了。

LOVA 不适合的：界面、图形、实时输入、浮点计算，以及要靠人手维护的代码。这些是为了换取上面那些保证而放弃的。

### 正确率那个数字，到底量的是什么

60/60 是真的，但没有看上去那么厉害。LOVABench 的题本来就是*用* LOVA 出的，v2 的题面直接把公式写出来了 —— "计算 p(tau(sigma(n)))"。所以拿 Claude 当基线量到的是**把公式抄成 s 表达式的能力**，不是编程能力。可以把它读成"模型写得出这种语法"—— 这值得知道 —— 但不能读成"模型会用 LOVA 编程"，它证明不了后者。要量后者，得有算法题库（Q33）。

### 密度那几个数字，到底量的是什么

两行密度数据要一起看，因为它们互相矛盾，矛盾本身就是结论。

8.5× 来自数论题：LOVA 那边是 `(sigma n)`，一个一字节的内建函数；Python 那边是 import 加一次 sympy 调用。这个比较把功劳记给了标准库。它能证明"领域定制的操作符集合有价值"，但量的不是写程序。

实验 12 量的是十道双方都没捷径、都得老老实实写算法的题：阶乘、斐波那契、素数判定、Collatz、欧几里得 gcd 等等。在这些题上，LOVA 第一阶段的 s 表达式**比 Python 多花 1.5 倍 token**，第二阶段形式也救不回来（0.65×）—— `(merge n -1)` 是七个 token，`n - 1` 只要三个；一个减一要花五个 AST 节点，换什么分词器都没用。

所以结论是：LOVA 在内建函数正好对上题目的地方很省，在一般算法代码上不如 Python 省。两个数字都留在表里。

实验 13 接着把这个差距拆开，发现改操作符表根本不对症：**第一阶段的 token 开销里 51% 是操作符名字，25% 是括号**。把名字缩短就能收回 30% 的差距，一个格子不用占 —— 是新加两个操作符收益的三倍；剩下 61% 是 s 表达式语法本身，64 个格子怎么排都碰不到。

实验 14 做出了能碰到它的东西。括号本来就是多余的：字节编码里没有分隔符，因为每个操作符的元数已经决定了结构，第一阶段花四分之一的 token 在重复底层早就知道的信息。第二阶段的形式就是把字节序列直接写成字符 ——

```
Stage 1   (defn square [n] (mul n n))(square 7)
Stage 2   W0\1*LL$A7;
```

—— 算法题从 0.66× 提到 **1.13×**，越过了 token 表永远达不到的 0.76× 天花板；LOVABench 对 sympy-Python 从 2.00× 提到 **5.38×**。往返 2150 次，无损。

所以老实的一句话结论不是"省 8.5 倍"，而是：**LOVA 的第二阶段形式在内建函数对上题目时比 sympy-Python 省 5.4 倍，对不上时省 1.1 倍。** 数字小了，但经得起挑刺。

这里面还有一件事没证明：模型能不能直接写第二阶段形式。理论上有 `valid_next` 应该比第一阶段还容易 —— 没有括号可以放错 —— 但没测过，是这个项目最要紧的开放问题（Q47）。

关于诚实：实验 11 第一次在 20 题的小集上跑出的是 2.5×/13.3×，换到 60 题的 v2 集就降到了 2.0×/8.5×，上面引的是后者。所有 NULL 结果、被削弱的结果，以及从实验 12 开始出现的负面结果，都有意留在日志里。

## LOVA 还做不到什么

直接列出来，因为条数不多，但每一条的缺口都不小：

- **它不是数据处理语言。** 原生虚拟机每秒一千多万步，一个游戏 tick 不到一毫秒，几万行文本的词频统计要几秒钟。几百万行的数据，或者需要向量指令的数值计算，现在还不是它的活（Q76）。
- **IO 只能整个读写。** `fs-read` 读整个文件，`net-recv` 收一整个数据报，没有句柄，没有流（Q72）。终端是环境自带的，不用声明（Q68）。
- **核心表满了，新东西只能往表外加。** 63 个核心操作符加 `END`；文本族（0x40-0x4F，M25 加入，M32 加满）是第一次突破 64，再要加操作符就得从数论族里挤（Q74）。
- **模块是文本级引入。** `(use "name")` 把 `lib/name.lova` 引进来，只引一次、可传递，`drop-unused` 让它零成本 —— 但两个库定义了同名的东西，后引入的会盖住先引入的，没有命名空间（Q50 就此关闭）。
- **种群是独立的值类型，不是程序列表。** 这样暂时绕开了泛型列表的问题（Q42）；长远看 `List<T>` 还是更好的做法（Q63）。
- **`head` 只在运行时检查。** cons 单元可以装任何值 —— M17 起树和程序列表都能表示 —— 所以 `head` 的返回类型取决于列表里装了什么，静态检查看不出来。有了 `List<T>` 才能找回静态类型（Q63）。
- **参数没有类型。** 检查器能从 lambda 推出函数的形状 —— 参数个数和返回类型（M20），所以部分应用放错位置、调用结果放错格子都是编译错误；但 LOVA 没有参数类型标注，函数体里把参数用错了，要等到运行时用到那个值才会报（Q43）。生成器也还只在 `Fn` 这一层工作（Q71）。
- **生成器写不出互递归。** M16 起生成状态机带作用域，所以生成出的程序里不会有未绑定或类型不对的引用（实验 16：704/1000 → 0）。但从左往右生成的机器没法引用后面才定义的东西，所以互相递归的 `def` —— M12 起就合法 —— 能编译，却生成不出来（Q64）。

## 渊源

LOVA 的架构词汇 —— PFS、守恒、血统、惊异、演化、Δ 安全 —— 来自 **DNA OS v3**，同一作者的另一个（未公开的）研究项目。概念是共用的，代码是独立重写的，不是分叉。

## 设计立场

决定每一处改动的只有一个问题：**AI 用它，是不是干得更多、更省事？** 公理是达成这个目标的手段，要给目标让路——从 2026-09-10 起，整数编码、"对人可读不是目标"、64 格上限和阶段一致性（公理 1、2、8、10）都只是设计偏好，不是否决权。一个改动要有实测的数字撑着才能进来，不管它对底层意味着什么；没有数字支持的功能，历史再久也只是提案。

语言里也没有任何盈亏或奖励目标。用户用守恒契约和惊异预算表达自己的目标，底层只负责执行。
