# Experiment 18 — The agent loop: the four numbers, measured

**Date:** 2026-09-10
**Script:** `experiments/experiment_18_agent_loop.py`
**Status:** Done, first run (pilot: one session per language). **PARTIAL.**

## Hypothesis

`spec/ai-convenience.md` turns the one goal into four numbers: attempts
from the first emission to green, feedback context read per failure,
tokens emitted across attempts, and the scaffolding a host needs. Exp
17 measured the single-shot special case of the first and found parity.
The claim to test here is the loop: a fresh agent that runs its code,
reads what came back and fixes it needs no more attempts in LOVA than
in Python, reads less to understand each failure, and needs less
outside it to be run safely.

## Method

Ten tasks that need loops, lists and text, none of them in LOVABench
and none with a built-in shortcut in either language: balanced
parentheses, reverse Polish evaluation, longest increasing run, Roman
numerals, the k-th smallest of two sorted lists, binary search, the
most frequent word, the trace of a matrix squared, runs of equal
characters, minimum coin change. Three hidden tests each, generated by
Python oracles.

Two Claude sessions with no project context and no repository access,
one per language, each told the rules of the measurement and given
one command, `submit`, which runs the answer against the hidden tests
and prints the feedback: `PASS`, or the first failure with the inputs,
the expected value, and either the value returned or -- for LOVA -- the
structured anomaly (kind, excerpt, line and column, repair hint, span)
and -- for Python -- the last thirty lines of the traceback. The LOVA
session also had `patch` (replace one span of the last submission,
counted as the size of the replacement). The LOVA session had the
generated one-page card (`corpus/language_card.md`) and nothing else;
the Python session had nothing, because it needs nothing. Up to eight
attempts per task. Every submission is logged with the characters
emitted and the characters of feedback printed
(`experiments/results_18/<lang>/log.jsonl`); `report` adds them up.

Scaffolding is recorded, not measured: a LOVA answer runs in-process
under a 200 000-node budget with no capability granted; a Python
answer runs in a subprocess under a ten-second wall clock, because
nothing in the language bounds it.

Before the sessions ran, the harness was tried by hand with two
reference solutions. The first LOVA trial hit `(map text-int ...)`:
an operator passed by name where a function value is expected, an
`unbound-ref` whose hint listed fifty name ids. The hint was rewritten
that morning to speak in names -- "`text-int` is an operator, not a
function value ... wrap it: `(lambda x0 (text-int x0))`", with the
nearest bound names for a misspelling -- and the sessions ran against
the rewritten hint. That is recorded here because the one LOVA
failure below is the same mistake.

## Results

| | LOVA | Python |
|---|---|---|
| tasks green | 10 / 10 | 10 / 10 |
| attempts (10 tasks) | **11** | **10** |
| tasks green at first attempt | 9 | 10 |
| feedback read, all failures | 1 114 chars (one failure) | 0 (no failure) |
| emitted, all attempts | 3 184 chars | 2 431 chars |
| emitted per task, median | 252 | 242 |
| `patch` used | 0 times | n/a |
| scaffolding | in-process, node budget, no grant | subprocess, wall-clock timeout |
| session wall time | 124 s | 54 s |

The one LOVA failure (t02, reverse Polish): the session wrote a helper
`(apply-op f st)` and called it with `merge`, `sub`, `mul` by name. The
compile error named the excerpt, the line and column, and gave the
lambda wrapper; the second submission, with the three wrappers, passed.
The session did not use `patch`, since the fix touched three sites.

After the run the feedback for that failure was measured again: 823
chars with the name-id list dropped from the anomaly (the names are
now listed instead, and the hint carries the nearest ones).

The sessions' own accounts, verbatim in substance:

- LOVA: "the one failure I hit produced a structured anomaly with the
  exact excerpt, line/col, and a `repair_hint` that contained the
  correct replacement code -- I did not have to reason about it at
  all." Hindered: the card did not say whether `nth` is 0-based (the
  session wrote its own indexer three times rather than trust it), did
  not say that operators cannot be passed as values ("a single sentence
  on the card ... would have made this a 10/10 first-attempt run"),
  listed `map-count` without a description, and the anomaly's list of
  bound-name ids "was most of the feedback's bulk".
- Python: "each task mapped directly onto a standard textbook
  algorithm, so no feedback beyond the PASS line was ever needed or
  read ... the measurement therefore says nothing about the quality of
  the FAIL diagnostics, which never fired."

All three card gaps were closed the same day (`nth` and `map-count`
carry notes in the prelude, which the card is generated from; the
operators-are-not-values sentence is on the card), and the id list is
gone from the anomaly.

## Findings

- **F1. Attempts: 11 against 10.** One more round in LOVA on ten tasks.
  The round was a card omission (operators are not values), not a
  language fault, and it was closed by the hint in one try. Python
  needed no round at all. *(pilot, one session each)*
- **F2. Feedback context could not be compared.** Number two of the
  yardstick is defined per failure, and Python had none. What the run
  shows is one side: a LOVA compile fault costs about 800-1 100 chars
  to read and the reading was sufficient, in that the fix was right
  first time.
- **F3. Emission: LOVA 31% more characters** over the run, 4% more per
  task at the median. Exp 12's density result at Stage 1 stands; the
  retry accounts for the rest.
- **F4. Scaffolding is the difference the loop makes visible.** The
  LOVA runner is a function call: a budget in the call, no capability
  granted, a runaway or a file read reported by name. The Python runner
  is a subprocess with a timeout, and a hostile answer would need more
  than that. This is the number where the design is strongest, and it
  is a property of the runner, not of the model's experience of the
  language.
- **F5. The hint was the loop.** The session read the hint, did not
  deliberate, and emitted the fix. A hint that carries the replacement
  is worth more to an agent than a span it could patch: `patch` went
  unused because the fault was conceptual and in three places.
- **F6. The card is the language.** Two of the three hindrances the
  session named were sentences missing from the card; the third was a
  list of integers in the feedback. Nothing in the language itself
  hindered it. For a model that writes LOVA from one page, the page's
  omissions are the language's faults.

## Discussion

The honest reading: on tasks of this size a fresh Claude writes both
languages correctly first time, LOVA once less so, and the loop as
measured cannot yet separate them on the numbers where the design
should win, because number two needs failures and number four (reuse,
repair, tracing) was not exercised. The difference the run does show
is number three: what the host needs around the code. That one is a
property of LOVA's runtime and holds at any task size.

The finding to act on is F6. Every hindrance the session reported was
a gap in the page, and the page is generated: closing the gaps was
three comment lines and one sentence. The card, not the token table,
is where a day's work moves the first number now.

What the next run needs: tasks where a first attempt fails in both
languages, so number two is measured on both sides -- longer
specifications (the `apps/` programs' size), more sessions (ten each,
the journal's own rule), and the reuse leg: hand a session a program
already written and a variant task.
